# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Always returns `{"status": "ok"}` 200 without checking MongoDB connectivity. | MongoDB down or invalid URI; `/health` still returns 200 instead of 503 per contract. | Pinged database with `client.admin.command("ping")` in `try/except`, raising 503 on failure. |
| 2 | Startup indexes (missing) | No database indexes created on application startup. | Concurrent duplicate `emp_code` or `(emp_code, date)` creates race conditions; queries/explains perform COLLSCAN. | Added FastAPI `lifespan` handler creating unique and composite indexes on `employees` and `attendance_logs`. |
| 3 | `create_employee` (lines 78-85) | Check-then-insert race condition; no validation that `shift_start != shift_end`; `created_at` stored as naive datetime and returned as datetime instead of epoch ms. | Concurrent duplicate creates can race; equal shift start/end returns 201 instead of 422; `created_at` response schema validation error. | Relied on unique index on `emp_code` catching `DuplicateKeyError` (409); added `shift_start == shift_end` check (422); stored UTC datetime and converted `created_at` to integer epoch ms. |
| 4 | `list_employees` (lines 89-96) | Pagination skip bug `skip = page * page_size` skips first 20 records on page 1; `total` counts entire collection ignoring filter; missing sort; returns BSON datetime. | Page 1 omits first 20 records; filtering by department returns entire collection count in `total`; unsorted results. | Fixed skip to `(page - 1) * page_size`; set `total = count_documents(q)`; added `.sort("emp_code", ASCENDING)`; formatted `created_at` to epoch ms. |
| 5 | `compute_late_minutes` (lines 33-37) | Ignores timezone; mixes naive/aware dates; strict inequality `minutes > 10` on floor minutes drops boundary 10:00:01 (601s should be 10m, but 601//60 = 10 not > 10); breaks on overnight shifts. | 09:30 shift with 09:40:01 punch-in returned 0 instead of 10 late minutes (violating R2 example); overnight shift punch-in past midnight miscalculates day. | Compared elapsed seconds between IST punch-in and IST shift start datetime on attendance date: if elapsed seconds > 600, returns `int(elapsed // 60)`, else 0. |
| 6 | `compute_work_hours` (lines 40-42) | Uses Python built-in `round()`, which applies Banker's rounding (half-to-even) rather than R4/R8 half-up rounding. | Work intervals yielding exact half values (e.g. .005) round to even numbers instead of rounding half-up. | Implemented `round_half_up` helper using `decimal.Decimal` with `ROUND_HALF_UP`. |
| 7 | `compute_overtime` (lines 44-48) | Missing 30-minute minimum threshold; ignores overnight shifts where shift_end falls on next calendar day; causes offset-naive vs aware subtraction errors. | Overtime of 15 minutes returned 15 instead of 0; overnight shifts (e.g. 22:00-06:00) calculated negative difference or crashed with TypeError. | Advanced shift_end by 1 day for overnight shifts (`shift_end <= shift_start`); returned minutes only if >= 30, else 0; ensured timezone-aware IST datetimes. |
| 8 | `punch_in` (lines 100-121) | Crashes with 500 if employee not found; check-then-insert race; attendance date computed from local clock ignoring IST and overnight shifts (R1); non-presence status allowed; exposes `id`/`_id` and raw datetime. | Unknown employee causes 500; overnight punch-in at 05:00 IST gets wrong date; status `ABSENT` accepted; response violates schema. | Checked employee exists (404); computed date via R1 overnight rules; enforced presence status; caught `DuplicateKeyError` (409); stripped `_id`/`id` and returned epoch ms. |
| 9 | `list_attendance` (lines 125-151) | Loads entire collection into Python memory with `list(...)` and sorts in Python; missing `emp_code ASC` secondary sort; lacks `date_from > date_to` validation; exposes `id`/`_id` and raw datetimes. | High memory and latency on 100k docs; `date_from > date_to` returned 200 instead of 422; tie-break order omitted; response schema violations. | Delegated query, sort `[("date", -1), ("emp_code", 1)]`, skip, and limit directly to MongoDB index; added `date_from > date_to` validation (422); formatted dates to epoch ms. |
| 10 | Missing endpoints | Starter lacked punch-out, regularization, employee monthly, department summary, late leaderboard, department trend, and explain endpoints. | Endpoints returned 404 Not Found. | Implemented all required endpoints following `openapi.yaml` contracts, business rules R1-R10, atomic updates, and MongoDB aggregation pipelines. |

Also note anything you looked at and decided was **not** a defect, and why:
- `IST = timezone(timedelta(hours=5, minutes=30))`: India Standard Time does not observe Daylight Saving Time, so a constant UTC+05:30 offset is fixed and correct.
- Storing calendar dates and shift times as strings (`YYYY-MM-DD` and `HH:MM`): Defined explicitly by `DATA_MODEL.md` to prevent unintended timezone skews across systems.
